# Шахматы с картами

Игра против локального ИИ, ChatGPT через OpenAI API, вдвоём на одном компьютере или по сети. Java 21 и Spring Boot управляют запуском, правилами и ИИ; React + TypeScript отображают игру. Для локального ИИ и игры вдвоём интернет и аккаунты не нужны. Для ChatGPT требуются интернет и API-ключ OpenAI.

## Запуск

Backend собирается Maven через включённый Maven Wrapper; отдельно устанавливать Maven не нужно. В IDEA откройте корневой `pom.xml` как Maven-проект или нажмите «Load Maven Changes», оставьте JDK 21. Точка запуска — `chess.server.Server`.

Из корня проекта:

```sh
sh scripts/start.sh
```

Откройте <http://127.0.0.1:8080>. В меню «Новая игра» выбираются соперник, сложность и лимит руки от 1 до 12. По умолчанию игрок играет белыми против ИИ, максимум три карты. Для остановки сервера нажмите Ctrl+C в терминале.

Начальный порядок фигур задаётся в `application.yml` параметром `chess.game.back-rank: RNBQKBNR`.

Начальные параметры задаются в `application.yml`: `chess.game.default-mode` выбирает соперника при локальном запуске, а `chess.game.opponents.ai`, `.chatgpt`, `.network`, `.human` содержат `hand-limit` и `difficulty` для каждого режима. Встроенный YAML содержит все значения по умолчанию; локальный файл может переопределять только нужные поля. В Railway при настроенных кодах доступа сервер начинает сетевую партию с параметрами `network`. Локальная форма предлагает «Локальный ИИ», «ChatGPT» и «Вдвоём»; в ней выбирается сложность ИИ, а вместимость руки берётся из настроек. В Railway доступны игра с другом по сети (по умолчанию) и ChatGPT. Для новой партии с ChatGPT обязателен ввод API-ключа. Локальный ИИ и режим одного устройства в облаке недоступны. Полный сброс снова применяет значения конфигурации, загрузка файла сохраняет параметры записанной партии. `hand-limit` — вместимость руки, начальная рука пустая. Сложность управляет поиском локального ИИ; в режимах с человеком она не меняет правила.

### Игра по сети

Для размещения в интернете: [пошаговая инструкция Railway](docs/RAILWAY.md).

1. Запустите сервер на своём компьютере. Откройте `http://localhost:8080` и выберите «Новая игра» → «По сети». Владелец играет белыми; для определения владельца используйте именно localhost или 127.0.0.1.
2. Второй игрок в той же сети открывает `http://ВАШ_IP:8080`. Доступные адреса сервер печатает в консоли при запуске. Первый удалённый браузер занимает чёрных; другой браузер не может занять это место. При запросе macOS разрешите Java входящие соединения.
3. Каждый видит только свои карты, число карт соперника и общую доску. Чёрным доска развёрнута. Состояние обновляется примерно раз в секунду; сервер проверяет сторону, очередь и версию каждого хода. Разведка раскрывается только владельцу карты.

Место чёрных закрепляется HttpOnly-cookie: после обновления страницы игрок остаётся чёрными. Не используйте разные браузеры для переподключения. Перезапуск сервера освобождает место; сохранённую сетевую партию можно восстановить кнопкой загрузки владельца, после чего второй игрок подключается снова. Создание партии, сохранение полного файла, загрузка и запросы к ИИ доступны только владельцу на localhost.

Сервер слушает все сетевые интерфейсы на указанном порту. Для подключения через интернет вместо локальной сети нужен доступный адрес и настройка маршрутизатора/сетевого доступа; одного частного IP за NAT недостаточно.

На этом компьютере JDK установлен внутри `.tools/`; скрипты находят его автоматически. Он не изменяет системную Java. Для переноса проекта установите JDK 21 или новее и задайте `JAVA_HOME`. Node.js 20.19+ или 22.12+ нужен только для сборки интерфейса. При первой установке зависимостей потребуется интернет:

```sh
cd frontend
npm install --registry=https://registry.npmjs.org
cd ..
sh scripts/build.sh
sh scripts/start.sh
```

`start.sh` собирает отсутствующие результаты автоматически. После изменения исходников выполните `sh scripts/build.sh` и перезапустите сервер. Для другого порта: `sh scripts/start.sh 8081`.

## Игра с ChatGPT

В меню «Новая игра» выберите «С ChatGPT». Вы играете белыми; модель выбирает ходы и карты за чёрных.
Сервер отправляет в Responses API позицию, руку ChatGPT и допустимые действия. Перед запросом фильтр исключает найденные матовые угрозы и варианты, уступающие лучшему по короткой материальной проверке более чем на 75 пунктов (пешка — 100). Проверяются ответные взятия, продолжение размена на той же клетке и возможность применения своей карты; подтверждённый мат в один ход имеет приоритет. Проверка не гарантирует отсутствие глубоких комбинаций. Карты человека и
порядок колоды скрыты. Исключение — две верхние карты после применения ChatGPT разведки.
Разведка требует двух запросов. Каждый ответ проверяется по актуальным правилам и версии партии.
Если рука неполная, а добор проходит проверку безопасности и нет шаха, выигрыша материала или конкретного сильного продолжения, сервер выбирает добор до лимита руки вместо выжидания. Шах и угроза потери фигуры имеют приоритет.
При ошибке API партия остаётся на текущем этапе; нажмите «Повторить ход соперника».
В `application.yml` параметры `openai.response-timeout: 10s` и `openai.max-retries: 10` задают время ожидания одного ответа и число повторов. При HTTP 502 интерфейс автоматически повторяет запрос до десяти раз после первой попытки
(максимум одиннадцать запросов), с паузами 1–4 секунды. Общая длительность всех попыток может быть больше 10 секунд. Другие ошибки, включая устаревшую версию,
не повторяются. Повторы могут создавать дополнительные оплачиваемые запросы API. Локальный ИИ не подменяет ChatGPT.

При локальном запуске ключ ChatGPT берётся из `openai.api-key` в `application.yml`; поля для ввода ключа и пункта сетевой игры нет. В Railway новая партия по умолчанию с другом по сети, оба игрока входят по своим кодам. При выборе ChatGPT нужно ввести API-ключ в защищённое поле. Он хранится только в памяти сервера, очищается из поля при закрытии окна и не записывается в файл партии.

Настройки находятся в `application.yml` в корне проекта:

```yaml
openai:
  api-key: "сюда-вставьте-API-ключ"
  model: "gpt-6-luna"
```

Откройте файл в IDEA, вставьте ключ и перезапустите Server. Working directory должен быть корнем
проекта. Ключ читает только Java-сервер; браузер его не получает. `application.yml` исключён из Git,
а `application.example.yml` содержит пример без ключа. Если локального файла нет, скопируйте пример.
Не отправляйте заполненный файл в чат. API оплачивается отдельно.

Можно выбрать доступную вашему API-проекту модель с поддержкой Structured Outputs. Настройки
заполняются Spring Boot через `OpenAiProperties`; YAML больше не разбирается вручную.
Встроенные значения поддерживают `OPENAI_API_KEY` и `OPENAI_MODEL` для Railway без локального файла.
В собственном YAML можно использовать `${OPENAI_API_KEY:}` и `${OPENAI_MODEL:gpt-6-luna}`,
как в примере, или явные значения. Приоритет источников соответствует Spring Boot.
Пустая модель считается ошибкой настройки; пустой ключ означает, что ChatGPT не настроен.
Для `gpt-6-luna` запросы используют `reasoning.effort: none`, чтобы сократить ожидание.
Доступны стандартный YAML, подстановка переменных и другие секции настроек Spring Boot.

Промпт соперника находится в `prompts/chatgpt-opponent.txt` (UTF-8). Его можно редактировать
отдельно от Java-кода. Сервер читает файл при запуске: после изменения промпта достаточно
перезапустить Server, повторная сборка не нужна. При отсутствующем или пустом файле запуск
завершается с понятным сообщением об ошибке.

После обновления проекта сначала выполните `sh scripts/build.sh`, перезапустите Java-сервер и
обновите страницу. Уже запущенный сервер продолжает использовать прежние Java-классы.

Документация API: <https://developers.openai.com/api/docs/guides/structured-outputs>.

## Правила

За ход выполняется одно действие: обычный ход, добор или применение одной карты. Игроки начинают без карт. При полной руке добор запрещён; сброса из руки нет. Общая колода содержит 44 карты — по две каждого из 22 типов, использованные карты перемешиваются после её исчерпания.

При шахе нельзя брать карту. Ход или сохранённая карта должны сразу устранить шах. Мат проверяется с учётом спасения картами. Рокировка, взятие на проходе и выбор фигуры при превращении поддерживаются.

| Карта | Копий | Действие |
|---|---:|---|
| Усиление пешки | 2 | Движение вперёд до двух клеток; первым ходом со стартового ряда — до трёх. Взятие обычное. |
| Усиление короля | 2 | До двух клеток по одному из восьми направлений; промежуточная клетка свободна и безопасна. |
| Возрождение пешки | 2 | Взятая пешка возвращается обычной на свободную клетку стартового пешечного ряда. |
| Возрождение фигуры | 2 | Возвращает взятую фигуру кроме пешки и короля на свободную исходную клетку её типа. |
| Смена стороны | 2 | Вражеская пешка меняет владельца и направление. |
| Заморозка | 2 | Вражеская фигура, кроме короля, не может ходить до конца второго действия владельца; продолжает атаковать. |
| Астрал | 2 | Вражеская фигура, кроме короля, исчезает до конца второго действия владельца. Не атакует, недоступна для карт, клетка зарезервирована. |
| Щит | 2 | Своя фигура, кроме короля, недоступна для вражеских карт до любого её хода. Обычное взятие разрешено. |
| Очищение | 2 | Снимает все эффекты с фигуры на доске. |
| Перестановка | 2 | Меняет местами соседние свои фигуры, кроме короля. |
| Разведка | 2 | Показывает две верхние карты и позволяет поменять их порядок. |
| Обмен планами | 2 | Меняет выбранную другую карту из руки на случайную карту противника. |
| Отмена хода | 2 | Отменяет последний ход фигурой и замораживает вернувшуюся фигуру на одно её действие. Восстанавливает взятия, рокировку и пешку после превращения; карты и добор не отменяет. |
| Увеличить снизу / сверху / слева / справа | По 2 | Добавляет одну пустую линию с указанной стороны, считая со стороны белых. |
| Уничтожить карту | 2 | Навсегда удаляет случайную карту из руки противника, без раскрытия типа. |
| Принести в жертву | 2 | Удаляет свою фигуру кроме пешки и короля и создаёт пешку на выбранной свободной исходной пешечной клетке. Жертва не доступна для возрождения. |
| Капкан | 2 | Видимое фиолетовое поле на пустой клетке, существует три круга. Вошедшая фигура замораживается на три последующих своих действия. |
| Невидимый капкан | 2 | Такой же капкан; координаты видит только создавший его игрок. |
| Белая дыра | 2 | Светящееся поле на пустой клетке на три круга. Запрещает вход, появление фигур и движение по линии; конь может перепрыгнуть. Не перекрывает атаки и шах. |

Усиление накладывается отдельным действием и расходуется после **любого** следующего движения фигуры. Одновременно могут действовать несколько разных эффектов. Щит запрещает вражеское очищение, но разрешает собственное. Возрождение не восстанавливает право на рокировку. Возрождённая пешка может сделать обычный двойной первый ход.

Уточнения для неоднозначных случаев в первой версии:

- Зарезервированная клетка астрала перекрывает линии движения и атаки. При проверке законности действия учитывается возвращение фигуры в конце хода.
- Усиленный двойной ход пешки допускает обычное взятие на проходе. Тройной ход его не создаёт. Любое действие соперника завершает окно взятия на проходе.
- Перестановка расходует усиления и щиты обеих перемещённых фигур и не может поставить пешку на крайний ряд.
- Применение разведки фиксируется **до** раскрытия карт: отменить его после просмотра нельзя. При одной карте в колоде использованные карты перемешиваются и добавляются под неё.
- Заявление ничьей доступно после 100 обычных ходов без движения пешки или взятия либо трёх повторений полного состояния. Автоматические пороги — 150 ходов и пять повторений. Изменяющие доску карты сбрасывают счётчик; для повторений учитываются карты, эффекты, взятые фигуры и колода. Обычная проверка «недостаточно материала» не применяется, поскольку фигуры можно воскресить.

## ИИ

Java-соперник использует итеративный minimax с alpha-beta: постепенно увеличивает глубину в пределах бюджета. Ходы фигур, добор и все доступные карты проходят общий фильтр непосредственных потерь и мата, затем участвуют в поиске. В спокойной позиции безопасный добор пополняет руку до лимита. На границе поиска дополнительно проверяются взятия, превращения и карты, а при шахе — все способы спасения. Оценка учитывает материал, незащищённые фигуры, укрытие короля, эффекты и полезность руки.

`Ai` — точка входа, `SearchEngine` — поиск, `ActionOrdering` — порядок действий, `GameProperties.search` — ограничения из YAML, `PositionEvaluator` — оценка. Лёгкая сложность: до 2 полуходов / 250 узлов / 0,5 с; обычная: до 4 / 1400 / 1,5 с; сложная: до 5 / 4500 / 3 с. Тактическое продолжение — до двух дополнительных полуходов. Возвращается результат последней завершённой глубины; генерация одного списка легальных действий может немного выйти за временной бюджет. При равной оценке выбор стабилен.

Настоящие карты человека и порядок колоды заменяются неизвестными картами **до поиска**. Противник учитывает количество скрытых карт и среднюю полезность добора, но пока не моделирует возможные вражеские заклинания подробно. Это базовый ИИ для пробных партий, не шахматный движок турнирного уровня.

Кнопка «Сохранить партию» записывает текущую партию в `data/saved-game.json`. Сохраняются фигуры, эффекты, обе руки, порядок колоды, сброс, история, очередь хода и настройки соперника. После перезапуска сервера нажмите «Продолжить сохранённую», чтобы восстановить позицию. Есть один слот: повторное сохранение заменяет предыдущий снимок. Сохранение ручное; перед выходом нажмите кнопку. Каталог `data/` не попадает в Git.

«Сохранить в файл» скачивает полный JSON-снимок в выбранное браузером место. «Загрузить из файла» позволяет выбрать такой снимок и продолжить партию, включая режим соперника и очередь хода. Повреждённый файл не заменяет текущую партию. API-ключ в сохранение не включается.

Перезагрузка страницы сохраняет текущую позицию в памяти сервера. Один сервер обслуживает одну общую локальную партию.

## Проверки и разработка

Добавление новых карт без ручной регистрации: [аннотации и реестр](docs/CARDS.md).

Приложение разделено на слои: `GameController` принимает HTTP-запросы и формирует ответы; `GameService` выполняет сценарии игры, а `PlayerAccessService` проверяет доступ игроков. Пакет `model` содержит данные запросов, результатов и ролей без зависимости от HTTP. `HttpRequestReader` проверяет заголовки и читает JSON, `HttpJson` сериализует ответы. Обычные команды выполняются атомарно под монитором сессии; долгий расчёт ИИ освобождает его, проверяя версию перед записью результата.

```sh
sh scripts/test.sh
node scripts/test-ui.mjs
sh scripts/build.sh
```

Тесты покрывают шахматные позиции 20 / 400 / 8902, основные действия всех типов карт, шах и спасение от обычного мата, длительность эффектов, рокировку, взятие на проходе, превращение, скрытую информацию ИИ и JSON.

Отдельные проверки сессии проверяют версии, одновременные команды, стабильность истории в ответе API и изоляцию состояния ИИ. Проверки интерфейса проверяют руки разного размера, скрытие карт, ориентацию доски и значки модификаторов.

При работающем сервере HTTP-проверка запускается командой `node scripts/smoke.mjs`. Она проверяет API и создаёт новую тестовую партию; в конце возвращает начальную партию против ИИ.

Чтобы проверка не затрагивала текущую партию, запустите отдельный сервер командой `sh scripts/start.sh 8081`, затем выполните `node scripts/smoke.mjs http://127.0.0.1:8081`.

Для разработки запустите Java-сервер, затем в другом терминале:

```sh
cd frontend
npm run dev
```

Vite открывает интерфейс на <http://127.0.0.1:5173> и пересылает `/api` на Java-сервер.

## Структура кода

Java-пакеты находятся в `backend/src/main/java/chess/`:

```text
chess/
├── game/     — партия, действия, правила, сессия, представление состояния
├── board/    — доска, геометрия и расширение по краям
├── pieces/   — абстрактная Piece, шесть наследников, эффекты и PieceFactory
├── cards/    — абстрактная Card, интерфейс PieceTargetedCard, каталог и реализации в impl/
├── ai/       — поиск действия и оценка позиции
├── opponent/ — абстрактный Opponent, реализации соперников и выбор по режиму
├── controller/ — HTTP-контроллер игры
├── service/  — сценарии игры и проверка доступа
├── model/    — модели запросов, результатов и данных доступа
├── api/      — чтение HTTP-запросов и сериализация ответов
├── server/   — запуск сервера и раздача интерфейса
└── serialization/ — общие настройки Gson и чтение JSON-объектов
```

Это пакеты одного Java-приложения. `game` использует доску из `board` и модели из `pieces` и `cards`; `ai` работает через публичные методы `Game`. Сессия выбирает наследника `Opponent` через `OpponentRegistry`: `LocalAiOpponent`, `ChatGptOpponent`, `NetworkOpponent` или `HumanOpponent`. Конкретные компьютерные реализации подключает `ApplicationConfig`. `MoveSelector` остаётся небольшим интерфейсом для подмены стратегии в тестах. Сетевой и локальный человек отправляют действия вручную; вызов автоматического хода для них запрещён. После загрузки сохранения реализация заново выбирается по сохранённому режиму. Внешний код получает копии фигур и неизменяемые списки карт; изменяемые коллекции партии доступны только внутри игрового пакета.

`Game` хранит состояние партии, создаёт копии позиции и принимает игровые команды. Внутренний `TurnRules` собирает допустимые действия, исполняет их и завершает полуход; `GameOutcome` проверяет мат, пат, повторения и ничьи; `ActionDescription` формирует записи истории. `MoveRules` собирает ходы и атаки через методы фигур и применяет выбранный ход к партии. `CardRules` расходует карту и передаёт исполнение наследнику `Card`; правила целей и эффект каждого типа находятся в отдельном классе пакета `cards`. `PieceTargetedCard` описывает карты для фигур, а `CardContext` связывает их с игровым ядром. `CardCatalog.create(id, type)` используется при создании колоды и загрузке сохранений; строковые типы и формат JSON сохранены. `GameView` создаёт снимок состояния без зависимости от HTTP. Маскирование скрытых карт находится в `Game.observationForCurrentPlayer()`; сессия передаёт сопернику эту копию. `Action` выделен в отдельный класс. Размеры, координаты и содержимое доски находятся в `board/Board.java`; прежний статический `BoardCoordinates` удалён.

Тесты находятся в `backend/src/test/java/`. `scripts/compile-java.sh` вызывает Maven; `--tests` компилирует и тестовые классы. Результаты находятся в `backend/target/`, исполняемый Spring Boot JAR — `backend/target/card-chess.jar`. `scripts/test.sh` запускает JUnit, включая прежние сценарии и проверки реестра карт. Точка запуска: `chess.server.Server`; она содержит только запуск Spring. `config/ApplicationConfig` создаёт зависимости, `ServerProperties` читает и проверяет порт и ключи доступа. `server/GameServer` управляет HTTP-сервером, а `StaticFileHandler` раздаёт интерфейс.

Интерфейс:

- `frontend/src/main.tsx` — только запуск React.
- `App.tsx` — сборка игрового экрана из компонентов.
- `hooks/useGame.ts` — запросы, переход хода, выбор фигур и карт.
- `game/` — типы API, клиент запросов, тексты карт и подсказки.
- `components/` — доска, рука карт, диалоги, правила и значки.
- `styles/` — общие стили, доска, карты, диалоги и адаптация к размеру экрана.

## Расширяемая доска

`Board` по умолчанию создаёт пустую доску 8×8; конструктор `Board(width, height)` поддерживает прямоугольные размеры. Доска хранит фигуры, проверяет границы и самостоятельно выполняет глубокое копирование. Правила ходов, атаки, ИИ и интерфейс используют текущую ширину и высоту вместо фиксированных 64 клеток.

Для карт расширения используются `addColumns(perSide)` — добавить вертикали с обеих сторон, `addRows(perSide)` — горизонтали сверху и снизу, а также `expand(left, right, bottom, top)`. Новые клетки пустые. Прежние фигуры сохраняют взаимное положение, факт движения и все эффекты. Геометрия хранит смещение исходной области, поэтому рокировка и возрождение остаются привязаны к прежним стартовым клеткам. Индексы текущей сетки меняются при расширении; `Board.Expansion.remap()` переносит связанные координаты. Внутренний `Game.expandBoard()` также переносит клетку взятия на проходе и очищает счётчик повторений прежней геометрии. Будущая карта должна вызывать эту операцию из обычного цикла действия, который обновляет версию партии.

Подготовленное правило для расширенной доски: пешки превращаются на новом внешнем краю; первые двойные и усиленные тройные ходы сохраняют привязку к исходному пешечному ряду. Буквенные подписи вертикалей продолжаются после h и z. Цвета прежних клеток сохраняются, подписи отображают координаты текущей сетки. API возвращает `boardSize` с шириной, высотой и смещением исходной области; интерфейс поддерживает прямоугольную сетку и её переворот.

Четыре карты расширения включены в колоду и доступны через API и интерфейс. Обычные партии начинаются на доске 8×8. Максимальный размер — 128×128. Проверки покрывают вставки с разных сторон, независимость копий, прямоугольные доски, фигуры на новых клетках, длинные ходы, рокировку, возрождение, взятие на проходе, превращение, ИИ и отображение.

## История и память ChatGPT

Каждый запрос включает полную публичную историю текущей партии. При следующих решениях сервер
сравнивает собственные фигуры соперника с предыдущей позицией и сохраняет наблюдения о потерях
или смене стороны в `data/chatgpt-memory.json`. До 30 последних заметок передаются модели
как `learnedLessons`, в том числе в новых партиях и после перезапуска сервера. Это контекстная
память, а не обучение весов модели и не гарантия усиления игры. Потеря может быть оправданным разменом.
Новые наблюдения появляются при следующем запросе ChatGPT; итог партии отдельно не анализируется.
После перезапуска сохраняются заметки, но не незавершённое сравнение позиций. Каталог `data/`
исключён из Git. Для сброса памяти удалите файл при остановленном сервере.

Оба автоматических соперника используют общий тактический фильтр: при наличии альтернатив
исключаются найденные матовые ответы и материальные потери, уступающие лучшему варианту более
чем на 75 сотых пешки. Проверяется продолжение разменов, включая обратные взятия и собственные карты.
Затем локальный поиск оценивает оставшиеся действия. ChatGPT получает оценки последней полностью
завершённой глубины и выбирает среди близких к лучшему: допуск 100 сотых пешки при глубине от двух,
70 при глубине один. Если первая итерация не завершилась, дополнительного отсева нет.
Модель сама выбирает ход из предложенного списка. Ограничения поиска и скрытые карты означают,
что ошибки и исключение оправданных глубоких жертв всё ещё возможны.

## Расход токенов

Общие инструкции сокращены и сохраняют стабильный префикс; запрос использует `prompt_cache_key`
для повторного использования префикса OpenAI, когда кэш доступен. Схема ответа постоянна:
список допустимых действий передаётся единожды вместе с тактическими оценками; ответ проверяется
локально. Доска, эффекты, карты и полная история имеют компактную запись. Из локальной памяти
передаются восемь последних заметок (на диске остаются до 30). При единственном допустимом
кандидате API не вызывается. В консоли Server выводятся input/cached/output токены из usage.
Кэш не гарантирован; сокращение числа символов не равно точному сокращению токенов. Связывание
запросов через previous_response_id не применяется: накопленные позиции также учитывались бы
во входных токенах. Лимит генерации оставлен 2048, чтобы не увеличивать ошибки незавершённых ответов.

`Piece` хранит общее состояние и эффекты фигур. Конкретные классы `Pawn`, `Knight`, `Bishop`, `Rook`, `Queen`, `King` определяют тип; `PieceFactory` создаёт их по прежним кодам P/N/B/R/Q/K при расстановке, возрождении и загрузке. Превращение пешки заменяет объект, сохраняя идентификатор и состояние. `moves()` и `attacks()` реализованы в классах фигур. `SlidingPiece` содержит общий обход лучей, а `MovementContext` предоставляет данные доски, право взятия на проходе и условия рокировки. `King` проверяет промежуточный шаг усиления и возможность рокировки; окончательную безопасность своего короля после любого действия проверяет `TurnRules`.

Ограничения поиска локального ИИ задаются в `chess.game.search.easy`, `.normal`, `.hard`: `depth`, `nodes`, `milliseconds`. Отдельный `SearchSettings` удалён; `Ai` получает конфигурацию при создании. После изменения YAML перезапустите сервер.

## Поля заклинаний и отмена

Капкан и белая дыра существуют три полных круга (шесть действий обеих сторон), включая ближайшее действие соперника. Капкан действует на обе стороны, включая короля и фигуру со щитом; он срабатывает при ходе, рокировке, перестановке и создании фигуры. Заморозка от входа длится три следующих действия владельца и может продолжаться после исчезновения поля. Пока поле существует, оно может сработать повторно. Белая дыра также запрещает возрождение и создание пешки на своей клетке. Создать поле можно на пустой клетке без другого видимого поля; скрытый чужой капкан может быть заменён вслепую, чтобы список допустимых целей не раскрывал его.

Невидимый капкан не передаётся противнику ни в API состояния, ни через историю и список целей, ни в наблюдение ИИ. Полный файл сохранения содержит все поля. На общем компьютере скрытые поля закрываются при передаче хода вместе с рукой. После расширения поля сохраняют положение относительно прежних клеток.

Отмена действует только сразу после хода фигурой. Время, очередь, руки и колода не откатываются: применение отмены само расходует действие. Восстанавливаются доска, взятые фигуры, права рокировки и окно взятия на проходе; уже истёкшие эффекты не продлеваются. Запись отменённого хода остаётся в истории вместе с записью отмены. Снимок последнего хода и поля сохраняются в файле; старые сохранения без этих полей читаются, но отменить ход до такого сохранения нельзя. Старая сохранённая колода не дополняется новыми картами автоматически: для полного нового набора начните новую партию.

При выборе корневого хода поиск учитывает потерю темпа: немедленный тихий возврат коня или слона по маршруту прошлого собственного действия получает штраф 90 сотых пешки. Это мягкая оценка, не запрет: при шахе, взятии, шахе противнику или отсутствии альтернатив отступление остаётся доступным. После расширения доски старые координаты истории для этой проверки не используются. Проверка позиции перед 14-м действием сохранена в `KnightReturnTest`.

Оценка `KingSafety` учитывает сохранённые права рокировки, укрытие короля и опасность раннего выхода при наличии тяжёлых фигур противника. Тихая необязательная утрата последней возможности рокировки получает дополнительную цену 90 сотых пешки; рокировка, спасение от шаха, взятие и шах противнику этим штрафом не ограничиваются. В окончаниях без тяжёлых фигур ценность укрытия снижается, активные ходы короля разрешены. ChatGPT получает `castlingRights` для обеих сторон: `[короткая, длинная]`, независимо от временной доступности пути. Регрессия перед 32-м действием проверяется в `CastlingChoiceTest`.

Матовая атака имеет приоритет перед сбором материала даже при неизвестных картах противника. Подсказки различают `mateInOne` — проверенный мат без неизвестных спасений — и `mateThreat` — отсутствие ответов по доступной позиции, когда скрытая карта ещё может спасти. Наличие скрытой руки не исключает такую атаку в пользу взятия пешки. Окончание партии по-прежнему проверяется сервером по всем реальным картам, поэтому доступное карточное спасение не теряется. Регрессия 138-го действия на доске 8×9 проверяется в `MissedMateTest`; платный API для проверок не используется.

`KnightMobility` оценивает нехватку безопасных выходов: конь без них получает штраф 90 сотых пешки, с одним выходом — 20. Варианты берутся из правил фигуры и учитывают размеры доски, эффекты и белые дыры; безопасность выходов оценивается по текущим атакам, а не доказывается полным поиском. Это помогает заранее освободить путь пешкой вместо выжидания до нападения. Уже вынужденная потеря не исправляется бегством на клетку, где коня заберут без компенсации. Регрессии перед 34-м, 36-м и 38-м действиями проверяет `KnightEscapeTest`.

Шаховые вилки конём проверяет `CheckingForkAnalysis`: ответный шах, все законные защиты, последующее взятие и обратный размен. При взятии фигуры с собственным шахом дополнительно проверяется, не сохраняется ли вилка после вынужденного ответа противника. Восстановленные позиции перед 64-м и 66-м действиями на 8×10 покрыты `CheckingForkTest`. Поле кандидата `checkingForkReplyId` указывает ответ, начинающий такую линию; её материальный результат входит в `worstMaterialDeltaAfterRecapture`. Собственные карточные спасения и заморозка вошедшего коня учитываются; замороженный конь продолжает давать шах.

При перевесе не менее 450 сотых пешки, наличии активной ладьи/ферзя и материале противника не более 500 `EndgameConversion` оценивает ограничение выходов короля, оттеснение к краю и приближение своего короля. Обязательное пополнение руки отключается; добор получает цену потери темпа. Это не запрет добора при отсутствии других законных действий. Проверка пата остаётся в поиске.

В такой позиции `MatingSearch` отдельно ищет мат через шах за два своих хода, проверяя все доступные ответы. Он получает до четверти времени (не более 300 мс) и до трети узлов (не более 2000) из общего бюджета поиска; остаток передаётся обычному поиску. Непроверенная до конца линия не принимается. `SearchResult.matePlies` отличает найденную линию от полной итерации поиска: при такой линии depth=0 и scores пуст. ChatGPT исполняет единственный отобранный первый ход без платного запроса. Скрытая рука противника остаётся неизвестной, поэтому линия условна относительно возможного неизвестного карточного спасения; настоящий результат партии всегда проверяется по реальным картам. Проверки включают мат в два, расширенную доску, пат и отсутствие бессмысленного добора.

Оценка реализации перевеса также считает связанную область безопасных клеток, доступную королю при неподвижных атакующих фигурах: уменьшение этой области полезнее бессмысленного преследования. При ладейном матовании учитывается приближение собственного короля к отсекающей линии. Это геометрическая эвристика, окончательную законность, шах и пат проверяет поиск. В выигранном окончании штрафуются обратные ходы короля/тяжёлых фигур и повторение того же хода в последних 32 действиях; найденный мат имеет приоритет. Полные проверочные окончания с ферзём, с ладьёй и на расширенной доске играются против короля, выбирающего более открытое пространство, и завершаются матом в пределах заданного числа действий. Это регрессионные сценарии, а не доказательство безошибочного матования против любой защиты.

## Android

Локальный ИИ и игра вдвоём работают без интернета и сервера. Партия автоматически сохраняется на устройстве. Для дополнительного режима ChatGPT требуются интернет и собственный ключ.
