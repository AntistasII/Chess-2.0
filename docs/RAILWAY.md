# Railway: игра с другом

Проект собирается корневым `Dockerfile`: React и Java 21 находятся в одном сервисе. Реальный `application.yml`, локальные сохранения и ключи не входят в Docker-контекст.

1. Подключите GitHub-репозиторий `AntistasII/Chess-2.0` к сервису Railway. Root Directory — корень репозитория. Dockerfile обнаруживается автоматически; отдельные Build/Start Command не нужны.
2. В Variables самостоятельно задайте `CHESS_HOST_KEY` и `CHESS_GUEST_KEY`: разные случайные секретные коды длиной минимум 16 символов. Первый предназначен владельцу, второй — другу. Не публикуйте коды в GitHub или URL. Без них облачный сервер отказывается запускаться.
3. Примените изменения / Deploy. Сервер слушает `0.0.0.0` и порт из `PORT`, который предоставляет Railway. Healthcheck Path — `/health`.
4. В Settings → Networking → Public Networking создайте Railway-домен. Используйте HTTPS. Если требуется target port, он должен совпадать с портом сервера из логов / `PORT`.
5. Откройте полученный HTTPS-адрес и введите код владельца. Вы играете белыми и управляете партией. Друг открывает тот же адрес и вводит код приглашения — он играет чёрными. Код владельца другу не передавайте.
6. Сервис должен иметь одну реплику: партия хранится в памяти одного Java-процесса. В облачном режиме сразу запускается сетевая партия. После перезапуска каждый входит своим кодом заново.

## Сохранения

«Сохранить в файл» скачивает полный снимок на компьютер владельца; его можно восстановить после перезапуска сервиса через «Загрузить из файла».

Чтобы локальная кнопка «Сохранить» сохраняла данные между развёртываниями, подключите Railway Volume к `/app/data`. Без Volume файлы контейнера не являются постоянным хранилищем. Даже с Volume после запуска требуется вручную нажать «Продолжить сохранённую»; автозагрузка не включена.

## ChatGPT

Для сетевой игры с другом API-ключ не нужен. Для отдельной игры против ChatGPT задайте в Variables `OPENAI_API_KEY` и, при необходимости, `OPENAI_MODEL`. Ключ вводите непосредственно в Railway, не в GitHub. Доступ к настройкам партии и запросам ИИ есть только у владельца.

## Проверка и ошибки

- `/health` отвечает `200` после запуска.
- Неавторизованный `/api/state` отвечает `401`; прокси или loopback не дают права владельца в облачном режиме.
- `Задайте разные CHESS_HOST_KEY...` — отсутствуют коды, они короче 16 символов или совпадают.
- `Railpack could not determine how to build` — в выбранной ветке/корне нет `Dockerfile`.
- `Недопустимый источник запроса` — открывайте домен по HTTPS, фронтенд и API должны обслуживаться одним доменом.
