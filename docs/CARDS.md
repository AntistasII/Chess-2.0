# Добавление карт через аннотации

Конкретные карты находятся в `chess.cards.impl` и его подпакетах. Spring сканирует `@CardDefinition` и автоматически строит реестр и колоду. Ручного `switch` и списка количества копий в каталоге больше нет.

```java
@CardDefinition(type = CardType.FREEZE, copies = 2, durationTurns = 2)
public final class FreezeCard extends TargetedCard {
    public FreezeCard(int id) {
        super(id, CardType.FREEZE, "Заморозка");
    }
    // Проверка цели и применение эффекта.
}
```

Для нового типа:

1. Добавьте стабильное значение в `CardType`.
2. Добавьте класс с аннотацией и публичным конструктором `(int id)`, реализуйте его действия.
3. Для нового визуального вида обновите описание и отображение во frontend.

Реестр и колоду править не нужно. `copies = 0` позволяет зарегистрировать тип без добавления в колоду; для `UNKNOWN` обязательно ноль. Типы в старых сохранениях продолжают загружаться через `CardCatalog.create(id, type)`.

При запуске проверяются дубли типов, отрицательное количество копий, отсутствующие реализации, абстрактные классы, конструктор и соответствие типа аннотации типу экземпляра. Карты не singleton-бины: фабрика каждый раз создаёт отдельный экземпляр со своим id. Реестр — Spring-bean, а неизменяемые экземпляры карт используются игровыми копиями.

Spring Boot управляет запуском и остановкой существующего HTTP-сервера. Формат API, cookies, проверка стороны и версии сохраняются. `PORT` Railway, коды владельца/приглашения и `/health` поддерживаются прежним способом.

`durationTurns` в `@CardDefinition` задаёт длительность в действиях владельца цели. Для FREEZE и ASTRAL установлено 2. Их реализации используют `effectEndsAt(context.ply())`; числовой срок в applyTo не дублируется. Ноль означает отсутствие фиксированной длительности, например щит действует до движения.


## Новые семейства карт

- `ExpansionCard`: четыре реализации `ExpandBottomCard`, `ExpandTopCard`, `ExpandLeftCard`, `ExpandRightCard`. По две копии каждой в колоде; расширение ограничено размером 128×128.
- `SquareEffectCard`: `TrapCard`, `HiddenTrapCard`, `WhiteHoleCard`. `durationTurns = 3` задаёт три полных круга жизни клетки; у капканов `freezeTurns = 3` задаёт три последующих действия владельца вошедшей фигуры. Значения передаются клиенту вместе с состоянием поля.
- `UndoMoveCard`: `durationTurns = 1` задаёт заморозку вернувшейся фигуры. `MoveUndo` хранит шахматную часть последнего действия без рекурсивных снимков, рук и колоды.
- `DestroyCard`: удалённая чужая карта не попадает в сброс и больше не возвращается в колоду.
- `SacrificeCard`: `to` — клетка жертвы, `other` — выбранная стартовая клетка новой пешки. Разрешена также клетка, освобождаемая самой жертвой. Удалённая фигура не попадает в список для возрождения.

Все эффекты проходят `TurnRules`: проверку короля, завершение действия, окончание сроков и смену очереди. Клеточные эффекты хранятся отдельно от фигур, входят в сохранения и ключ повторений. При расширении их индексы переносятся вместе с исходными клетками. Чужой скрытый капкан удаляется из наблюдения ИИ и представления API, не подписывается координатами в истории и не исключает свою клетку из списка целей другого клеточного заклинания.

Проверки: `sh scripts/maven.sh test`, frontend `npm --prefix frontend run build`. `node scripts/new-cards-smoke.mjs http://127.0.0.1:8084` выполняет сценарии карт на отдельном сервере, заменяет его партию и оставляет расширенную позицию для ручной проверки интерфейса.
